# 通用设备通道 REST API

约定:Base URL `http://<host>:4317`(默认);除 [POST /api/pair](#post-apipair-配对唯一免鉴权) 外全部需要 `Authorization: Bearer <token>`。请求与响应均为 JSON(UTF-8)。`POST` 请求体上限 64KB。

携带 `Origin` 头的请求:Origin 的**主机名必须是服务端本机地址**(`127.0.0.1` / `localhost` / 本机任一 LAN IPv4)且**端口必须等于通道监听端口**(缺省端口按协议默认 80/443 折算)——本机其他端口上的服务可伪造同主机名 Origin,只比主机名拦不住;不符即 `403`。原生设备客户端不发 Origin,不受影响。

## POST /api/pair(配对——唯一免鉴权)

用桌面显示的一次性配对码换取长期凭据。

**请求**

```json
{ "code": "498661", "deviceName": "我的手机" }
```

- `code`:桌面「机器人 → 通用设备」生成的 6 位数字码,**5 分钟有效、一次性、原子消费**(并发同码恰好一个成功)。
- `deviceName`:全局唯一(去首尾空格、截断 40 字符、过滤控制字符;NFKC 归一化后不分大小写比较)。重名 → `409`,**配对码不消耗**,换名同码重试即可。缺省时服务端填「通用设备」,但重名会拒,建议必填。

**响应 200**

```json
{ "deviceId": "dev_mwd1accw_hdp0", "token": "<43 字符 base64url>", "protocol": 1,
  "capabilities": ["turn-stream","session-stream","answers","deliveries","files","set-host","set-enabled","rename-device","self-revoke","session-archive","attachments"] }
```

**错误**:`400` 配对码缺失/不正确/已过期(码此时才作废,失败不烧码);`409` 设备重名(**码不烧**);`429` 超限(同 IP 10 次/分,或全局连续失败 20 次熔断——桌面重新出码即解除)。

安全细节:token 服务端密文存储;校验为恒时长比较;`deviceName` 在服务端净化(控制字符/零宽/bidi 移除)。

## GET /api/info

```json
{ "version": "33.4.11", "hostname": "MacBookProM1.local", "platform": "darwin",
  "firstRun": false, "protocol": 1,
  "capabilities": ["turn-stream","session-stream","answers","deliveries","files","set-host","set-enabled","rename-device","self-revoke","session-archive","attachments"] }
```

`firstRun` = 还没有任何**顶层会话**(成员会话/子智能体不计入,与 `/api/sessions` 列表同口径)。

设备端应在启动时记录 `protocol` 与 `capabilities`;不满足所需能力时提示升级,而非猜测语义。

## GET /api/sessions?limit=N

会话列表,按 `updatedAt` 倒序。**成员会话(子智能体)不进列表**(与桌面/IM 同口径)。`limit` 为正整数时返回前 N 条(`≤500`),响应另带 `total`(全量数)——设备端可用 `total > sessions.length` 判断截断。

```json
{ "sessions": [ { "id": "sess_…", "title": "…", "personaId": "…|null",
                  "personaName": "工程师|null(缺省)",
                  "lastMessage": "最后一条可见消息摘要,≤120 字符|缺省=空会话",
                  "updatedAt": 1730000000000, "busy": false, "archived": false } ],
  "total": 21 }
```

`busy=true` 表示该会话有正在运行的回合。`personaName` 由服务端把 `personaId` 解析成角色展示名(未绑定或角色已删除时字段缺省)——设备端画角色徽标无需再调角色清单接口。`lastMessage` 与 `/messages` 投影同口径(正文 text 块,跳过纯工具轮)。

`focusRoot`(聚焦工作区绝对路径,缺省=全机通用)供设备端目录分组;`pendingCard` 布尔=有未决交互卡(设备端「待操作」角标;由 asks/plans 边车判定)。**分类与排序由设备端按这些字段自定**(服务端恒按 `updatedAt` 倒序返回全量)。

## POST /api/sessions

新建空会话 → `{ "id": "sess_…" }`。标题由首轮消息自动派生,改名走 [`/rename`](#post-apisessionsidrename)。

**请求**:`{ "personaId"?: "<GET /api/personas 里的 id>" }`。带 `personaId` 即新建时选定角色——**沿桌面语义,首发落库后绑定不再改**;未知角色 `400`。`workspaceRoot` 仍为 **v2**(设备端给不出可信目录)。

---

## GET /api/sessions/:id

单会话元信息(**携带任意 query 不再 404,query 一律忽略**):

```json
{ "id": "sess_…", "title": "…", "personaId": "…|null", "personaName": "工程师|缺省",
  "focusRoot": "/abs/dir|缺省", "model": "providerId:modelId|缺省=跟随默认", "effort": "…|缺省",
  "busy": false, "archived": false, "pendingInserts": [], "pendingCard": false, "lastMessage": "…|缺省" }
```

`pendingInserts` v1 恒为空数组(插入消息走 send 的忙时回退,不落独立队列)。

## POST /api/sessions/:id/send

发送消息。**两种成功形状**:

| 场景 | 响应 | 设备端处理 |
|---|---|---|
| 会话空闲,发起新回合 | `{ "turnId": "turn_…" }` | 记录 turnId,订阅事件流,乐观上屏用户气泡 |
| 会话忙(有回合运行中) | `{ "inserted": true }` | 提示「已插入进行中的任务,当前步骤结束后送达」,**不新建订阅**(现有事件流会继续) |

**请求**:`{ "text": "…", "attachments"?: ["…"], "modelRef"?: "providerId:modelId", "effort"?: "…" }`。`attachments` 的合法值只能来自 [`POST /api/attachments`](#post-apiattachments-附件上传) 返回的 path(未登记路径一律「已忽略未授权文件」,不当读盘);**忙时插入只带正文**(附件被丢弃,与桌面/IM 同语义)。`modelRef`/`effort` v1 设备端可不发(桌面按默认解析)。

**错误**:`404` 会话不存在;`409` 忙且插入失败(罕见);`500` 其余(含模型未配置)。

发送成功后,**先订阅该会话的事件流,再认为消息已发出**(见[事件流](general-device-sse.mdx)的时序要点)。

## POST /api/sessions/:id/answer

应答交互卡。卡片由事件流的 `ask_user` / `plan_review` / `mount_request` 事件带来,`key` 为卡标识。**先到者生效**:一设备应答后服务端广播 `interaction_resolved`,其余设备同 key 再答 → `409`(并收到广播把卡收起)。

**请求**(按 `kind` 分三种 payload):

```jsonc
// kind = "ask":逐题作答,answers[i] 对应 questions[i];null 表示放弃
{ "key": "…", "kind": "ask", "payload": { "answers": ["Kotlin", "自由输入文本"] } }
// 放弃整卡:{ "payload": { "answers": null } }

// kind = "plan":"approve" 批准 / "keep" 带反馈继续完善 / "ignore" 取消
{ "key": "…", "kind": "plan", "payload": { "decision": "approve" } }
{ "key": "…", "kind": "plan", "payload": { "decision": "keep", "feedback": "再补一个…\n…" } }

// kind = "mount":设备端无法指定桌面真实路径,恒传 null(= 暂不挂载,指引去桌面)
{ "key": "…", "kind": "mount", "payload": { "path": null } }
```

**响应**:`{ "ok": true }`;**`409`** 卡已结束(先到者生效)——收到 `409` 时设备端应检查事件流的 `interaction_resolved` 帧把卡收起,而非重试。

## POST /api/turns/:turnId/abort

停止回合。幂等:未知/已结束的 turnId 也返回 `{ "ok": true }`。

---

## POST /api/sessions/:id/archive

归档 / 取消归档(与桌面「归档对话」同源):

**请求**:`{ "archived": true }`(`archived` 必填布尔)。

**响应**:`{ "ok": true, "archived": true }`。

**错误**:`404` 会话不存在;`409` 会话有正在运行的回合,不可归档(与桌面同口径;取消归档随时可以);`400` 缺 `archived`。归档后的会话仍出现在 `/api/sessions` 列表(带 `archived: true`),设备端自行决定展示方式(安卓端长按会话项操作)。

---

## POST /api/devices/self

**自助吊销本设备**(凭当前 Bearer token 自证身份,无需物理回到桌面):服务端按 token 反查 deviceId,走吊销全套清理(配置 + 密钥 + 活动态 + SSE 连接 + token 缓存)。

**请求**:无请求体。

**响应**:`{ "ok": true }`。**此后该 token 一律 `401`**(包括本请求之后的任何重放)——设备端成功后应立即清除本地凭据(deviceId/token),引导重新配对。典型场景:设备丢失/易主时远程自救。前提:攻击者尚未更改凭据;若怀疑凭据泄漏,应在桌面端吊销该设备。

---

## POST /api/attachments?name=…

附件上传(能力 `attachments`):设备端**只交字节、不交路径**——与桌面粘贴同一管道。

**请求**:原始文件字节作为请求体(非 JSON),`name` query 指定文件名(服务端净化),`Content-Type` 作为类型提示。上限 24MB(`413`),空体 `400`。

**响应**:`{ "path": "/abs/…", "name": "图片.png", "kind": "image" }`。`path` 仅供同 token 后续 send 的 `attachments[]` 使用。

- 类型/体积超上限(图片>5MB、PDF>20MB、文本>512KB)不拒绝,降级为「位置注入」:文件落盘、`kind:"file"`,模型按路径用工具读。
- 不支持的类型 → `400` 与原因文案。
- 白名单为内存态(随重启清空):上传后桌面重启,该路径 send 会被忽略。

## GET /api/tasks

定时任务**只读**清单(能力 `tasks`;创建/编辑在桌面端):

```json
{ "tasks": [ { "id": "task_…", "title": "…", "status": "active|paused|completed|error",
               "schedule": { "kind": "once|recurring", "at": "…|缺省", "cron": "…|缺省" },
               "scheduleText": "每天 09:00(服务端本地化的人读日程)",
               "sessionId": "task_…|缺省=独立运行" } ] }
```

`sessionId` = 任务独占会话,点击可进入该对话看历史运行。

## GET /api/models

可用模型清单 + 当前全局默认(能力 `models`;`ref` 可直接用于 send 的 `modelRef`——显式指定后本对话固定用它):

```json
{ "models": [ { "ref": "providerId:modelId", "name": "显示名", "provider": "提供方显示名" } ],
  "active": "providerId:modelId|null" }
```

不含密钥与 apiHost(非敏感明文项);口径与桌面模型解析同源。

## POST /api/sessions/:id/rename

重命名对话(能力 `session-rename`):**请求** `{ "title": "…" }`;空标题 = 恢复自动派生标题。**响应** `{ "ok": true, "title": "落库后的标题" }`。改名不改 `updatedAt`(列表顺序不变);`404` 会话不存在。

---

## DELETE /api/sessions/:id

删除对话(能力 `session-delete`):与桌面 `chat:delete-session` 同一实现——主对话连同成员会话一并删、在其中运行的定时任务改为**独立运行**、进行中的回合先中止。**响应** `{ "ok": true }`;`404` 不存在。不可恢复,设备端 UI 应二次确认。

---

## GET /api/sessions/:id/messages?start=&limit=

历史回填。`start` 为全量投影中的起点(默认 `total-400`,即最新一段),`limit` 上限 2000。**响应字段**:

```json
{ "sessionId": "…", "total": 312, "start": 0,
  "messages": [
    { "i": 0, "role": "user", "text": "…", "tools": [], "attachments": 0 },
    { "i": 1, "role": "assistant", "text": "…",
      "tools": ["present_files"],                       // 折叠工具行(名字)
      "files": [ { "path": "/abs/…", "name": "sample.png", "size": 69, "image": true } ],
      "card": { "kind": "ask", "key": "call_…",
                "questions": [ { "question": "…", "options": [{"label":"…","description":"…"}],
                                 "multiSelect": false, "required": true } ] }
    } ] }
```

- `card` 仅在该卡**尚无终态**时出现(未决卡);已答的卡不回填——设备端应答后靠 `interaction_resolved` 事件收起。
- `files` 为该消息交付的文件(仅在交付成功时出现);`path` 可直接用于 `/api/files`。
- `tools` 是工具名数组,设备端折叠为一行;`attachments` 是正文之外的附件个数。

## GET /api/sessions/:id/deliveries?toolUseId=…

一次 `present_files` 交付的文件清单(手机在直播中收到该工具的成功结果后调用):

```json
{ "files": [ { "path": "/abs/sample.png", "name": "sample.png", "size": 69, "image": true } ] }
```

## GET /api/files?path=…&session=…

下载交付文件。**白名单**:`path` 必须逐字出现在该会话的交付清单里(不接受任意路径),否则 `403`。响应为文件原始字节流,`Content-Type` 按扩展名。文件不存在(被移动/删除)→ `404`。

## SSE 订阅端点

| 端点 | 投递范围 |
|---|---|
| `GET /api/sessions/:id/events` | 该会话**全部回合**的 chat 帧 + 通知(**推荐**,设备端主用) |
| `GET /api/turns/:turnId/events` | 仅该回合的 chat 帧;**未知 turnId → `404`**(turn_start 入环即登记,设备端拿到的 turnId 必然已登记;被缓冲淘汰的老回合同 404) |

均支持 `Last-Event-ID` 头与 `?lastEventId=N` 等价的续传语义、心跳与连接治理。详见[事件流](general-device-sse.mdx)。

## 错误码约定

| 码 | 语义 | 设备端处理 |
|---|---|---|
| 400 | 参数/编码不合法 | 展示 `error` 文案 |
| 401 | 未配对/凭据无效/设备被停用 | 转「重新配对」流程,清除本地凭据 |
| 403 | 越权(白名单外路径、跨源 Origin) | 不重试,提示 |
| 404 | 会话/文件/回合不存在(回合级 SSE 未知 turnId) | 不重试 |
| 409 | 业务冲突:卡已结束(先到者生效)、忙且插入失败、忙时归档 | 拉最新状态,收卡/提示 |
| 429 | 限速(配对 10 次/分/IP,全局熔断 20 连败) | 退避 ≥60s,引导桌面重新出码 |
| 500 | 服务端内部错误 | 可重试一次,再失败提示 |

`error` 字段为人类可读中文文案,可直接展示。所有错误响应形如 `{ "error": "…" }`。
