# Deva 安卓客户端 v1 设计文档

状态：**评审版（待门禁）**。本文是先行的设计约束，实现以本文为准；实现中若发现本文与代码冲突，先改本文再改代码。

## 1. 目标与交付物

明天交付一个**可安装的 APK**：在安卓手机上连上本机 Deva，能看会话、发消息、看流式输出、答复问答/计划卡、看到交付文件。

验收环境：Android 8.0+（minSdk 26），compileSdk 35，JDK 17，Kotlin + Jetpack Compose（Material 3）。

**什么算成功（v1 验收线）**：

1. 手机上添加服务器（地址 + 配对码），连接成功并在断线后自动重连；
2. 会话列表可见、可切换、可新建；标题与桌面一致；
3. 发一条消息，能看到流式文本、工具状态行、最终正文，能停止；
4. 桌面端发起的回合，手机端也能实时看到（同一后端、同一会话）；
5. `ask_user` / `exit_plan` / `mount_request` 三类交互卡可以作答，且桌面端同步收起；
6. 交付文件能在手机上看到列表并下载/预览图片；
7. 全程不需要公网 IP，不引入任何云端中转。

**非目标（v1 明确不做，见 §9）**：成员/子智能体的完整管理、定时任务编辑、技能与 MCP 管理、设置页全部项、多服务器互联。

## 2. 关键现状与取舍

Deva 主进程目前**没有任何入站端点**（已核实：`apps/desktop/src/main` 全量检索 `createServer` / `.listen(` / `WebSocketServer` 零命中）。远程通道都是**主动出站**：Telegram 长轮询、飞书长连接。

因此安卓客户端不能"照抄 IM 适配器"（那等于把 Deva 变成 IM 平台），必须新增入站通道。三条路线的取舍：

| 方案 | 做法 | 优点 | 代价 | 结论 |
|---|---|---|---|---|
| A. 复用 Telegram（手机装 Telegram 用现有 bot） | 零新代码 | 立刻可用 | 不是"Deva 客户端"，UI 受 Telegram 限制 | 只作为兜底，不作为交付物 |
| B. 局域网直连（Deva 起 HTTP/WS + 安卓原生 App） | 无公网依赖、端到端直连、延迟低 | 需要配对与鉴权；离家不可用（可用组网工具补齐） | **v1 采用** |
| C. 公网中继 | 任何网络都可用 | 引入服务器与运维成本，违背"数据留在自己机器" | v2 再议 |

选 B 的理由：与 frog-bot 的形态一致（自托管 + 原生客户端），且不改变 Deva「本地优先、无需公网」的产品性质。离家可用性交给 Tailscale / WireGuard 这类用户已有工具，不写进产品。

**参考实现**：frog-bot 的安卓端（Kotlin + Compose，`android-claude/`）已把"自托管 AI 后端的原生客户端"这条路走通：登录拿 Cookie、SSE 长连接收事件、`Last-Event-ID` 断线续传、事件重放恢复状态、审批走独立接口、前台服务保活。Deva 客户端沿用这套骨架，但**事件模型、交互卡片、权限语义**全部对齐 Deva 自己的 `ChatStreamEvent` 与 `PromptView`，不做概念翻译。

## 3. Deva 侧新增：入站通道

在 `apps/desktop/src/main/services/` 下新增 `channel-server/`（命名待实现时定），职责单一：**把已存在的 chatRuntime 与 chat-bus 暴露给已配对的设备**，不复制任何业务规则。

> **协议通用化（2026-11-12 修订）**：入站通道不限定「安卓」——任何实现本协议（HTTP REST + SSE 长连接 + Bearer 鉴权）的设备都可接入，桌面「机器人」面板统称**通用设备（GeneralDevice）**。安卓 App 是该协议的首个实现。代码/IPC/类型命名一律用 general。

### 3.1 传输

- 进程内 `node:http` 起监听，默认端口 **4317**（可配置，配置存 `config.json`，键 `androidServer.{enabled,port,host}`）。
- 复用同一个 HTTP 服务器提供 **SSE**（`text/event-stream`）与 REST；不做 WebSocket（SSE 已满足单向事件推送，且实现与调试成本更低，frog-bot 也是 SSE）。
- 只监听 `127.0.0.1` 与局域网地址二选一：默认 **`0.0.0.0` 但要求配对后才可访问**；提供「仅本机」开关。
- 端口冲突时启动失败要明确回报，不静默改端口。

### 3.2 鉴权与配对（必须先于任何会话语义）

- 首次启用时生成一次性**配对码**（6 位数字，5 分钟有效），在桌面「机器人」面板的「通用设备」入口显示（列表置顶行 + 右侧详情，「+」菜单也提供通用设备项直达配对码），并附二维码（内容：`deva://pair?host=<host>&port=<port>&code=<code>`）。
- **设备名全局唯一**：配对时若设备名（去首尾空格、不分大小写）与已配对设备重名，配对拒绝（409），设备端需换名重试。
- **配对码一次性原子消费**：校验与作废在同一步同步完成（`consumePairCodeIfMatch`），并发同码配对有且只有一个成功——杜绝「校验→异步落密钥→作废」窗口期的双重接入竞态。
- 手机 `POST /api/pair { code, deviceName, devicePubKey }` → 返回 `{ deviceId, token }`；token 为随机 32 字节，落盘 `secrets.json`，键 `general:<deviceId>:token`（沿用现有 secrets 约定，**不复用 `remote:<botId>:*`**）。
- 之后所有请求带 `Authorization: Bearer <token>`；token 可在桌面端吊销（`DELETE /api/devices/:id`）。
- 失败限速：同 IP 每分钟 10 次配对尝试，超限 429。
- **明文 LAN 的边界**：v1 允许 http（局域网），但在桌面与手机两端都显式提示"当前为明文传输，建议仅在可信网络使用"；v2 提供自签证书 + 指纹校验。这条写进 §7 风险。

### 3.3 REST 接口（v1 面）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/pair` | 配对（唯一免鉴权接口） |
| GET | `/api/info` | 版本、主机名、平台、是否首次运行 |
| GET | `/api/sessions` | 会话列表（id/title/personaId/updatedAt/busy/archived） |
| POST | `/api/sessions` | 新建会话（可选 personaId / workspaceRoot） |
| GET | `/api/sessions/:id` | 单个会话元信息 + 待送达插入消息 |
| POST | `/api/sessions/:id/send` | 发消息（`text`, `attachments[]`, `modelRef?`, `effort?`） |
| POST | `/api/sessions/:id/answer` | 交互作答（`key`, `kind: ask/plan/mount`, `payload`） |
| POST | `/api/turns/:turnId/abort` | 停止回合 |
| GET | `/api/turns/:turnId/events?lastEventId=N` | SSE 事件流（支持 `Last-Event-ID` 续传） |
| GET | `/api/sessions/:id/messages` | 历史消息（分页，供进入会话时回填；含未决卡与交付文件投影） |
| GET | `/api/sessions/:id/deliveries?toolUseId=...` | 一次 present_files 交付的文件清单（直播回合收到 tool_result 后补拉） |
| GET | `/api/files?path=...&session=...` | 下载交付文件 / 预览图片（path 必须在该会话边车 delivered 白名单内） |

`send` 内部转调 `ChatRuntime.send`，`answer` 转调 `answerAsk` / `decidePlan` / `answerMount`，`abort` 转调 `abort`。**入站通道不得自己拼接提示词、不得绕过 `tools-policy` 权限闸门**——它与桌面 IPC 走同一入口，保证落盘、检查点、安全闸门一致。

### 3.4 事件流

订阅 `chat-bus.onChatEvent`（hub 就是这样接的）并转成 SSE 帧：

```
id: 123
event: chat
data: {"sessionId":"...","turnId":"...","type":"text_delta","text":"..."}
```

- `event` 取值仅 `chat`（`ChatStreamEvent` 原样透传）与 `notice`（`AppNotice`）。
- 每帧 `id` 单调递增，存在进程内环形缓冲（默认 2000 条/会话）；客户端带 `Last-Event-ID` 可补发增量，超出缓冲则返回 `replay_reset`，客户端重新拉 `/messages`。
- **不新增事件形状**：v1 直接把 `ChatStreamEvent` 的类型（`text_delta` / `thinking_delta` / `tool_call` / `tool_result` / `ask_user` / `plan_review` / `mount_request` / `todos` / `usage` / `reconnecting` / `stream_reset` / `auto_retry` / `error` / `compacted` / `compacting` / `interaction_resolved` / `card_resolved` / `turn_start` / `insert` / `inserts` / `inserts_returned` / `done` / `member_report` / `member_progress`）直接映射为 App 内的 sealed class，未知类型一律忽略并计数（便于后续版本兼容）。

### 3.5 生命周期

- 启停挂在主进程启动/退出时序上，位于 `stopAllChannels()` 之后停止（先停出站通道再停入站）。
- 状态纳入 `ChannelState` 同形的状态机（`off / connecting / connected / error`），桌面「机器人」面板的「安卓设备」详情显示通道状态、监听地址与已配对设备（配对时间 + 吊销）。
- 崩溃/异常不得影响聊天主流程：通道内部所有错误只上报状态，不抛给 chatRuntime。

## 4. 安卓端结构

技术栈：Kotlin 1.9+ / Compose Material 3 / OkHttp + 原生 `org.json`（与 frog-bot 一致，避免引入序列化框架的复杂度） / `EncryptedSharedPreferences` 存 token。

```
app/src/main/java/zai/deva/android/
  DevaApp.kt              Application，启动时装载服务器列表
  MainActivity.kt         单 Activity + Compose Navigation
  core/
    ServerConfig.kt       服务器条目（地址、设备名、deviceId），不存 token 明文
    DevaClient.kt         HTTP：登录、sessions、send、answer、abort、files
    EventStream.kt        SSE 客户端：Last-Event-ID、指数退避重连（1s→2s→…→30s，抖动 ±20%）
    SessionStore.kt       会话列表与消息缓存（内存 + Room 可选，v1 用内存）
    Timeline.kt           事件折叠成时间线（正文/思考/工具/卡片/交付物）
    SecureStore.kt        EncryptedSharedPreferences 封装
  ui/
    HomeScreen.kt         服务器 + 会话列表
    ChatScreen.kt         对话流 + 输入框 + 停止
    Cards.kt              问答 / 计划审阅 / 挂载请求 三类卡片
    FilesScreen.kt        交付文件列表与预览
    SettingsScreen.kt     服务器管理、配对、连接状态、明文提示
    Theme.kt              深色优先，与桌面一致的强调色
```

**状态机**：`Stopped → Connecting → Streaming → Waiting(input) → Done`。`Waiting` 只能由三类交互卡进入，此时输入框禁用并提示"等待你在下方卡片中作答"，防止用户打字却被静默丢弃。

**保活**：前台服务 + 常驻通知（可选开关），只在 App 退到后台且开启该选项时启用；v1 不申请 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`。

## 5. UI 信息架构（v1）

1. **服务器页**（首次启动）：添加服务器 → 扫二维码或手填 `host:port` + 配对码 → 连接。
2. **会话页**：顶部服务器切换器；列表按更新时间倒序；每项显示标题、角色徽标、忙/闲、最后一条消息摘要。
3. **对话页**：气泡流（用户右、助手左），工具调用折叠成一行"正在…"，可展开看参数摘要；底部固定输入框；右上停止按钮只在 `Streaming` 出现。
4. **卡片区**：紧贴对话末尾。问答卡支持单选/多选/自由输入；计划卡展示 Markdown 计划 + 「批准/继续完善/取消」三键；挂载请求卡显示路径 + 「挂载/跳过」。
5. **交付物**：对话内显示文件名与大小，点击下载到 `Downloads/Deva/`；图片直接内联预览。
6. **设置页**：服务器增删、断线重连、明文传输提示、关于。

视觉要求：深色主题优先，字号正文 ≥ 15sp，按钮可点区域 ≥ 44dp，长按可复制正文。

| 阶段 | 内容 | 出口判据 |

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 明文 LAN 传输 | 同网段可嗅探 | v1 显式提示 + 默认只允许配对设备；v2 自签证书 + 指纹 |
| 端口被占/防火墙 | 手机连不上 | 启动失败明确报错；设置页给出"检查防火墙/换端口"指引 |
| SSE 断线丢事件 | 界面停在半句话 | `Last-Event-ID` 续传 + `replay_reset` 触发整体回填 |
| `ChatStreamEvent` 演进 | 老版本 App 崩 | 未知事件类型忽略并计数，不抛异常 |
| 安卓后台被杀 | 收不到长回合结果 | 前台服务（可选）+ 重进 App 时整体回填 |
| 误把入站当出站通道写 | 两套语义分叉 | 通道只做转发，业务规则一律留在 chatRuntime / hub |

## 8. 与现有代码的边界（实现纪律）

- **不改** `chat.ts` 的回合语义、`tools-policy` 的权限判定、`hub.ts` 的 IM 绑定逻辑。
- 新增文件只落在 `channel-server/`、`src/preload` 的少量新增 IPC（`general:*`，用于桌面端显示配对码/设备列表）、`renderer` 机器人面板的「通用设备」入口（BotsPane + i18n）。
- 安卓工程放在 `apps/android/`（与 `apps/desktop` 平级），独立 Gradle 工程，不进 pnpm workspace。
- 任何对 `ChatStreamEvent` 的修改都要同步本文 §3.4 的表。

## 9. 明确不做（v1）

- 成员（`create_member`）与子智能体的管理与视图；
- 定时任务（`create_task`）的创建与编辑，只在列表里显示名称；
- 技能、MCP、插件、角色编辑；
- 多服务器互联（frog-bot 的 relay 能力）；
- 公网中继、邀请码分发、多用户；
- iOS / 桌面端改动。
